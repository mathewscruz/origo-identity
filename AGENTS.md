# AGENTS

- Scheduling lives only in the Hermes agent (agent/origo_iam_agent_executor.py SCHEDULE, via iam-agent-api POST /run_task with an allowlist); never add pg_cron jobs or DB-side function invokers — the agent is the single executor.
- Screen-triggered runs go to public.agent_tasks (RPC agent_task_solicitar); the Hermes claims them in GET /pending and reports via POST /task_result. Emergency stop is parametro agent_paused, honored server-side in /pending.
- No manual sync buttons in the UI: pages request refreshes via RPC `agent_refresh_request` (throttled, writes `agent_tasks`) through `useAutoRefresh`/`AutoUpdatedHint`; the Hermes executes them. Keeps the panel automatic without browser-side execution.
- Notifications to people: the panel writes `alertas`; the Hermes pulls them via iam-agent-api GET /notifications, sends through its own Telegram (HERMES_NOTIFY_CMD) and acks via POST /ack (`alertas.notificado_em`). No Telegram connector in the app.
- Activity feed copy lives in `src/lib/activityLabels.ts` (business sentences + noise filter), covered by `src/test/activity-labels.test.ts`.
- System connections: `aplicacoes.modo_acesso` (sso|grupo|api|manual) drives `iam_resource_template`; API mode stores create/disable/lookup templates in `aplicacao_connectors.config.actions` and the Hermes executes `create_user_app`/`disable_user_app` through iam-agent-api POST /app_api_execute (shared `_shared/appApi.ts`), so credentials never leave the backend; manual mode creates `manual_access_task`/`manual_revoke_task` closed by humans via `iam_manual_task_concluir`. The "Conectar sistema" chat only fills the ficha and links perfis via tools; credentials only in the protected connector form. Hermes retests all systems daily (`test-app-connection` modo todos).
- HR base enters only through `sync-sharepoint-csv`, triggered by the Hermes; the manual upload function was removed to keep a single writer.
- Dashboard entradas/saídas come from `dashboard_people_series`: executed `eventos_jml` joiner/leaver (dated by the successful queue create/disable), GLPI third-party creations and Hermes-confirmed joiner audits (`%joiner%created%`, people Hermes creates without a JML event); never from audit-only markers, so every real offboarding counts.
- Hermes also serves `agent_tasks` and Telegram notifications through the MCP tools `run_agent_tasks` / `list_pending_notifications` / `mark_notifications_sent` (RPCs `agent_task_claim`/`agent_task_finish`, same allowlist, honors `agent_paused`, 30-min stale lease reset), so an older Hermes server build still executes panel requests.
- Systems in Aplicações are registered only through "Conectar sistema"; Azure Enterprise Apps are no longer imported (sync-entra-apps removed from agent allowlists) so the catalog holds only governed systems.
- Analysis of a system's link/documentation in "Conectar sistema" is done only by the Hermes (agent_tasks `analyze-app-docs`, delivered via MCP `run_agent_tasks` → `submit_app_analysis`, excluded from iam-agent-api /pending); the panel never fetches/reads sites and uses no scraping service, and applies the diagnosis only after the user confirms (`src/lib/appAnalysis.ts` strips secrets).
